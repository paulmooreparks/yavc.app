# Initial content applet host audit

This is the historical first-batch audit. The subsequent Docs/Editor extraction, separate applets and Docker reintegration are recorded in `content-workspace-contract.md` and the extraction receipt in `applet-portability-design.md`. Its remaining downstream webview gate is still open.

The first implementation batch uses source baseline `02ce1da` and PUDL 0.103.0. The audit covers current source dependencies and documented contracts; it does not assert that an actual downstream host or the full editing extraction has passed acceptance.

| Area | Existing contract or dependency | First-batch result and remaining work |
| --- | --- | --- |
| Diagrams registration/lifecycle | Standard PUDL package, state callback, commands, ready promise and disposal | The real applet is installed unchanged in purpose by the minimal host kit. Embedded state no longer reads unrelated containing-page query parameters. Full pending-read/recovery lifecycle still needs coverage. |
| Asset paths | Diagrams and two shared-kit loaders assume `/applets/...` | Those loaders now resolve sibling package resources from the classic entry script's documented current-script URL. A different URL prefix loads the same modules without a server route alias. |
| Shared support | `yavcUtil`, dialogs and document tabs are currently owned under the web static directory | The artifact includes these actual source files as dependencies. The unrelated host creates no substitute site globals. Moving their authoritative source and removing optional site-FS assumptions remains extraction work. |
| Files | Documented host-kit `fs.readText`, `writeText`, Open and Save As | Legacy read/write has no expected revision. `content-resource-contract.md` specifies an experimental conditional resource extension and Diagrams uses it when explicitly supplied. The site backend is not upgraded by the client wrapper. |
| Write authority | Editor uses direct `F.write`; Slides/Diagrams use host file writes and per-document queues | Queues protect acknowledgement ownership, not competing storage writers. An actual storage-authority conditional adapter is still required before the writable cross-applet split. |
| Source preservation | Existing Markdown source-preserving blocks and JSON Canvas models | The unrelated-host fixture retains an unknown Canvas property through source editing/save. This is one regression, not the full Markdown/Canvas preservation audit. |

| D2 worker security | A dedicated worker response permits eval while the page forbids it | The first unrelated-host run reproduced the missing-worker-policy failure. The fixture now implements that exact isolation; a retained failure screenshot demonstrates the requirement. |

| Slides | Shared rich/source/Markdown modules plus presenter/window behavior | Shared-loader regressions must pass; presentation capability and the Slides shell remain part of the planned extraction/reintegration. |
| Package provenance | Existing package version does not identify the full dependency tree | The experimental build emits a complete file manifest and digest, compiling WASM and copying matching Go runtime assets. Release publication and actual webview acceptance are not claimed. |
| Module compatibility | Current shared engines expose cached module globals | The harness proves multiple mounts of one exact dependency set. Mixed versions in a receiving application remain unsupported until package compatibility checks and module isolation are specified; the harness is not proof of that case. |

The proof host keeps synthetic data only in memory. It demonstrates that loader paths, resource operations and the real rendering engines can be separated from the yavc shell, while exposing remaining host-contract gaps before an external application adopts the packages. The receiving application must keep its own snapshot/writer/creator, attachments, workspace policy and publication authority.

Source review found startup could join legacy recovery before refusing the experimental resource host, and initialization could create a fallback editor after disposal during its first read. Startup now refuses before joining any recovery provider; boot and state callbacks stop after disposal. The harness verifies zero snapshot registrations on refusal and no editor creation after a held initial read is released into a disposed mount. A separate cross-format regression keeps autocomplete state installed for source languages without providers, preventing a pending completion callback from finding no state after Canvas switches to Mermaid. The vendor bundle is unchanged.

## Dialog dependencies

The dialog overhaul uses the public PUDL listbox module for Canvas selection. A host can preload `pudl-listbox.js`; Diagrams otherwise loads it from the documented PUDL base URL before opening the selector. The optional yavc `fileFields` version 1 capability provides Browse and durable import, as specified in `file-fields-contract.md`. Hosts without it retain editable path fields and explain why Browse is unavailable. Packages must include these shared dialog dependencies in their artifact manifests. This source review does not claim a newly built independent artifact or desktop-webview acceptance.
