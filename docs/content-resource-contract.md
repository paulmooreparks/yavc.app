# Experimental content resource host contract, version 1

This contract is a yavc-owned, versioned host extension used by the initial Diagrams portability proof. It is not a claim that the current PUDL host kit or yavc.app storage already provides conditional writes. The host kit's documented `host(given)` preserves additional capabilities, so a proof host may supply `pudlHost.contentResources`. Adoption into any shared package contract requires a separate coordinated change. The legacy `fs.readText`/`writeText` path remains unchanged when this extension is absent.

## Host operations

The capability has `version: 1`, `read(request)` and an optional `write(request)`. Each method returns a promise. `read({resource})` returns `{resource, revision, text, writable}`. A resource is an opaque host-authority/workspace-scoped identity, not a URL to fetch or a globally meaningful path. `revision` is an opaque nonempty string. Text is a string with a maximum of 4,194,304 UTF-16 code units. Resource and revision tokens are limited to 4,096 code units. Both request and response resource IDs must agree.

`write({resource, expectedRevision, text})` atomically compares the expected revision at the host's storage authority and writes only if it still matches. A mismatch rejects without mutation. A successful write returns `{resource, revision, writable}`. Changed content requires a different revision; an unchanged save may keep a content-based revision. The acknowledgement represents the exact submitted text. A conflict, denied grant, deleted resource or failed write rejects with an error the applet can display. The host must not silently write another identity, substitute content or treat a broadcast/timestamp as atomic comparison. This interface cannot manufacture atomicity in a backend that lacks it.

The client validates responses and freezes issued snapshots. Only a snapshot issued by that client can authorize its write; copying a plain object from another mount/client does not carry that authority. The host still validates authorization at execution. This is a local client guard and does not replace host authentication, grant enforcement or concurrency protection.

Each Diagrams tab retains its loaded snapshot and advances that baseline only after an acknowledged write. Its existing per-tab queue captures submitted text and the opening tab instance. Newer edits remain dirty. Closing/reopening the same identity creates a different tab and cannot acknowledge an old completion. The host owns any write that finishes after disposal. Cancellation is not a guarantee that storage mutation stopped.

## Deliberate proof limits

The initial extension supports reading and conditional saving of an existing resource. Optional create-only destinations and host-owned Save As are defined in `content-creation-contract.md`; hosts without those operations retain existing-resource behavior. Unbound drafts can use Save As when supplied, while explicit agent destinations use create-only semantics. Recovery baselines are defined separately below. Attachment resolution, byte decoding, rename/delete and external-change subscription remain separate gates. Native resource keys are supplied by the host through PUDL's documented applet state event. Embedded mounts do not read the containing application's unrelated `file` query.

The applet refuses a host that combines this capability with a snapshot service older than version 2 before registering a provider. The versioned recovery adapter carries the original baseline revision and binds a dirty draft only when a fresh host read still matches it. Changed, unavailable and legacy unversioned drafts retain their text without gaining a new writable baseline. Snapshot validation precedes registration, alternate copies remain until replacement succeeds, and flush acknowledgement controls the reload guard. `content-recovery-contract.md` states this yavc-owned extension. A disposed mount also ignores awaited reads before creating a fallback draft.

`writable` controls persistence authority. The first proof established the resource boundary; subsequent batches added recovery, creation and the read-only source/visual command policy described in `diagram-resource-adoption.md`. Synthetic fixtures now cover writable and read-only resources, recovery and permission changes in save acknowledgements. Guest Diagrams adopts the prepared adapter; the complete Docs/Editor split is not yet enabled.

## Running the independent-host proof

`node scripts/build-portable-diagrams.mjs <new-output-directory>` builds both WASM engines from source, gathers their matching runtime loaders, and assembles Diagrams, shared modules, PUDL, support code, licenses and a disposable host fixture. The directory must be outside the checkout and must not exist. The build refuses symlink sources. `manifest.json` records every artifact file's length/hash, the source HEAD, Go toolchain and aggregate asset digest. Working-tree bytes are identified by those hashes; HEAD alone does not identify an uncommitted candidate.

`node scripts/test-portable-diagrams.cjs <output-directory> [chromium firefox webkit]` verifies file hashes and serves only that artifact beneath an unrelated URL prefix. It does not start the yavc server, load its guest filesystem/configuration, create a session cookie or touch real files. The fixture supplies two synthetic in-memory resources and conditional writes. It tests real D2 worker/WASM, Canvas and Markdown rendering, Mermaid, independent mounts, exact save submissions, edits during save, stale revision rejection, unknown Canvas-property retention and disposal. The package's own support scripts are included dependencies; the host does not fabricate `pcSiteFs` or `pcConfig` globals.

The page policy forbids JavaScript eval. Only the exact D2 worker response receives the existing documented worker policy, `default-src 'none'; script-src 'self' 'unsafe-eval' 'wasm-unsafe-eval'`. That worker can import the bundled runtime and evaluate D2's bundled layout code but cannot fetch resources. Other worker/page responses do not gain eval. A receiving host that cannot supply this isolation cannot claim D2 compatibility; enabling broad page eval is not an alternative. The contract follows [CSP's worker handling](https://www.w3.org/TR/CSP3/#csp-inheritance). Classic package scripts capture [document.currentScript](https://developer.mozilla.org/en-US/docs/Web/API/Document/currentScript) during initial execution; they do not inspect it later in callbacks or claim module-script support through that API.

The proof remains an experimental dependency artifact rather than a published standalone release or completed reintegration. Shared support modules still originate in the current source locations. Guest Diagrams, Editor and Slides now adopt the host conditional-write adapter. The remaining server-mount writers, source-preservation audit, package extraction, full host capability negotiation and actual receiving-webview acceptance remain separate gates.
