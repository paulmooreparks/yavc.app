# Canvas: freeform diagrams in JSON Canvas

Status: designed on 2026-11-04, with C1 merged and C2 implemented for review. Paul wants a diagram editor where shapes go where he puts them, as in Figma or draw.io. The D2 editor cannot be that editor, because D2 lays out every diagram itself and its free layout engines refuse positions. He chose two editors over one compromise, comparing the split to the Editor's `foo.md` and `foo.docs.md`, and asked that the second not become a language of our own. This design answers that with an existing open format, JSON Canvas, and keeps to what the format defines wherever it can.

In outline, a canvas is a `something.canvas` file in JSON Canvas 1.0. Diagrams opens it beside D2 and Mermaid, draws it with a renderer of the site's own, and edits it on a canvas where every shape and connector stays where it was put. The text of the file is still the whole diagram, shown beside the canvas as the D2 text is, so an agent, git and a reader of the raw file can all follow it.

## What the format provides

JSON Canvas 1.0 (2024-03-11, MIT licence, published by Obsidian) was read from its repository, `obsidianmd/jsoncanvas`, file `spec/1.0.md`. Its site, jsoncanvas.org, is outside this environment's network policy. The specification defines these parts.

- A file holds two arrays, `nodes` and `edges`, both optional. The order of `nodes` is the drawing order: the first is drawn below the rest and the last on top.
- Every node has an `id`, a `type`, integer `x`, `y`, `width` and `height` in pixels, and an optional `color`.
- There are four kinds of node. A `text` node holds Markdown. A `file` node holds a path, with an optional `subpath` that starts with `#`. A `link` node holds a `url`. A `group` node is "a visual container for nodes within it", with an optional `label` and an optional background picture.
- An edge has an `id`, a `fromNode` and a `toNode`, an optional `fromSide` and `toSide` (each `top`, `right`, `bottom` or `left`), an optional `fromEnd` and `toEnd` (each `none` or `arrow`, defaulting to no arrow at the start and an arrow at the end), an optional `color` and an optional `label`.
- A colour is a hex string or one of six presets, `"1"` to `"6"` (red, orange, yellow, green, cyan and purple). The specification leaves the presets' exact values to each application.

Three things matter for this design. The format has no shapes, since every node is a card. Its line ends are only an arrow or nothing. And the specification says nothing about properties it does not define: it neither allows nor forbids them, and says nothing about whether a reader must keep them. The repository's readme lists extensibility among the format's aims but defines no mechanism for it.

## Decisions

1. **A canvas is a JSON Canvas file** (2026-11-04, Paul chose to explore it). The file is `something.canvas`, the suffix the format names, and it is valid JSON Canvas 1.0. Everything that has a meaning in the specification is written the way the specification writes it: positions and sizes, text, groups, the sides and arrows of a connector, colours and labels. A file Diagrams writes therefore opens in Obsidian and any other JSON Canvas application, which show the same nodes in the same places joined by the same connectors.

2. **What the format lacks is one extension, kept apart and degrading to the format** (2026-11-04, recommended; open question 1). Shapes, connector routing, line styles and the richer line ends are written in a single property on a node or an edge, `"yavc"`, holding an object, for example `"yavc": {"shape": "cylinder"}`. Nothing else is added anywhere. Because the specification is silent about extra properties, the design assumes another application may drop the `"yavc"` objects when it saves, and every file must still be a sensible diagram without them: a cylinder becomes a card in the same place with the same text, and a crow's foot becomes an arrow or nothing. The extension is documented as a specification of its own in `docs/canvas-extension.md`, version 1, before the first file is written, so it is a stated dialect and not one implied by the code.

3. **Diagrams opens canvases, as the Editor opens documents** (2026-11-04). A canvas is a third kind of diagram in the Diagrams application, beside D2 and Mermaid, with the same tabs, files, export and embedding, and with its own toolbar of tools. This follows the comparison Paul drew: the Editor opens `foo.md` and `foo.docs.md` with one set of commands and a richer mode for the second, and Diagrams opens `foo.d2` and `foo.canvas` the same way.

4. **The text is still the model, and a gesture is one change to it** (2026-11-04). The Text view shows the file's JSON in CodeMirror, and Split shows it beside the canvas, as for D2. Every gesture on the canvas (a move, a resize, a new connector) is one replacement of the JSON text, made as one CodeMirror transaction, so Undo, Redo and the text view stay one thing, as decision 5 of `docs/diagrams-design.md` made them for D2. Diagrams writes the JSON in one stable form, two spaces of indent and each object's keys in the order the specification lists them, so a move changes two numbers on two lines and a git diff shows only that. Text typed by hand is kept as it is until the canvas next changes it.

5. **The site draws a canvas itself, as SVG it owns** (2026-11-04). The renderer turns a canvas into an SVG element made from numbers, escaped text and the site's own path for each shape, so every part of the drawing is an element the editor can hit-test, select and restyle exactly. This removes the problem the D2 editor has with lines it did not draw. A drawing for a document or an export is the same SVG, serialised and shown as an image, as a D2 diagram is (decision 10 of the Diagrams design).

6. **A text node's Markdown is drawn by the site's Markdown engine, cleaned** (2026-11-04; open question 2). On the canvas a text node's Markdown is drawn as HTML by the Markdown engine and the site's HTML cleaner, in a `foreignObject`, so headings, lists, emphasis and links look as they do in the Editor. In an exported SVG or PNG, where a `foreignObject` can stop a browser from making a picture, the same text is drawn as SVG text, with paragraphs, bold and italic kept and the rest reduced to plain text.

7. **Connectors are routed by the site, between the sides the file gives** (2026-11-04). A connector leaves its `fromSide` and arrives at its `toSide`. Where a side is not given, the router chooses the nearest pair of sides. The route is computed from the two boxes and the two sides, and nothing about it is stored except the style in the extension (`"route": "straight"`, `"elbow"` or `"curve"`, elbow by default). The same file therefore draws the same way every time, the drawing never disagrees with a stored path, and another application's own routing is not contradicted by data it would ignore.

8. **Placing is free, and snapping is an aid** (2026-11-04). A shape goes where the pointer puts it, in whole pixels, as the format requires. While a shape is dragged, it snaps to an 8-pixel grid and to the edges and centres of the shapes near it, showing a guide line for each match; holding Alt turns snapping off. The arrow keys move the selection by one pixel, and by eight with Shift. Align and Distribute act on a selection of several shapes. Resizing has handles on the corners and the sides, and keeps the proportions with Shift.

9. **Groups are the format's groups, containing by area** (2026-11-04). The specification defines a group as a visual container for the nodes within it and gives no list of members, so membership is by area: a node lies in a group when its box lies inside the group's. Moving a group moves the nodes inside it, and a node dragged out of a group's area leaves it. This is the reading the specification's own words give, and it needs no extension.

10. **Shapes are drawn to fit their box, and the set matches the D2 editor's palette** (2026-11-04). The extension's `shape` is one of rectangle, rounded, oval, diamond, parallelogram, document, cylinder, queue, person, cloud, hexagon, package and text, each drawn by the site to fill the node's box. By default, text starts at the top-left inset for rectangle, rounded, text, document and package shapes, and is centred in the usable interior of the others. The optional alignment properties override those defaults (decision 21). These are the shapes of the D2 editor's palette, so the two editors offer the same set and a diagram converts between them without losing kinds.

11. **Converting between the two kinds of diagram is a command, not a link** (2026-11-04). File, Convert to a Canvas lays out a D2 diagram once with D2, takes each shape's box from the compiled diagram (the documented `d2target` positions the D2 editor already reads), and writes a canvas with the same shapes, labels and connectors, which can then be arranged by hand. Convert to D2 does the reverse and leaves the positions behind, since D2 cannot hold them. Each writes a new file and leaves the original as it was, because the two formats do not stay in step.

12. **Embedding is the same as for D2** (2026-11-04). A canvas file embeds in a document or on a slide with the `{{diagram}}` shortcode the Diagrams design describes, and draws through this renderer. There is no fenced form, since JSON is not something to write inside a document.

13. **A canvas is untrusted, as every file is** (2026-11-04). The reader checks the JSON against the specification and the extension's own schema before drawing anything, and refuses a file over 2 MB or over 5,000 nodes and edges. A colour must be a hex colour or a preset. Text goes through the Markdown engine and the cleaner. A file node shows a picture only from the site or the home folder, and never loads one from another host. A link node shows its address as text and opens it only when pressed, in a new tab with no opener. A group's background picture follows the file node's rule.

14. **The PUDL rules hold on the canvas** (2026-11-04). The selection is the focus ring, handles are raised controls, the tools are a toolbar of raised buttons, the inspector is the D2 editor's form of sunken fields, and every gesture has a command with a menu row and a key. The canvas is arrowed through as the D2 canvas is, with Tab moving between shapes in drawing order, and an Outline pane lists every node and edge for a person who cannot use a pointer.

15. **Canvas editing has a model module and a view module** (2026-11-04). `apps/diagrams/canvas-model.js` applies validated edits without a DOM, preserving unknown file properties, and `canvas-view.js` provides the hit layer and editing camera. A pointer gesture previews its result until release, then submits one edit against the text it started on. Escape, pointer cancellation, a tab switch or a source change cancels the gesture. CodeMirror's documented `history` configuration and `joinToEvent` predicate keep each canvas edit separate from edits before and after it, including another gesture made immediately. The surrounding application supplies the shared dialogs, notices, commands and inspector.

16. **The camera belongs to the open tab** (2026-11-04). The editing view pans and zooms in file coordinates, including negative coordinates. Fit centres the contents and follows pane size until the person moves the camera or starts a gesture. Later edits preserve the camera. Export continues to use the renderer's content bounds, so panning or zooming changes neither the saved JSON nor the exported picture. This adopts the recommendation in open question 3. Wheel input pans, Ctrl or Command with the wheel zooms at the pointer, and Space with a drag or the Pan tool pans. View has matching pan and zoom commands, and 0 fits.

17. **A group carries the nodes fully inside its box** (2026-11-04). Containment includes the boundary. Moving a group moves each contained node once, including groups; resizing a group changes only its box. Deleting the group leaves the other nodes and their connectors. Copying or duplicating a group includes its contained nodes and the connectors whose endpoints are both copied, with fresh IDs on paste. Array order controls every node's drawing order, including groups. A new group starts behind existing nodes. Edit holds copy, paste, duplicate and delete; Shape holds creation, resizing, movement and ordering; Go and View hold selection navigation and camera commands.

18. **Either connector end can be reattached or left free** (2026-11-04, Paul requested endpoint dragging and automatic anchors). Selecting a connector exposes raised handles at its start and end. Dragging either handle can change its node or side, including the original node, or leave it at a free point. The central half of a node always means automatic attachment, including when zoomed out. Elsewhere, a drop within 12 screen pixels of a side-centre anchor pins that side, even just outside the outline; another interior drop also attaches automatically. Automatic attachment removes that end's side property. The router then chooses the closest pair of side-centre points, respecting any pinned side, whenever either node moves or resizes. Ties retain the centre-to-centre direction's preferred sides. Preview uses the same router, and the release is one undoable edit. Keyboard commands and the agent action expose the same reattachment.

19. **A free endpoint is a point node in the standard file** (2026-11-04). JSON Canvas requires both endpoint node IDs. Its integer dimensions allow zero, so a free point is an empty text node with zero width and height, `yavc.shape` set to `text` and `yavc.anchor` set to true. This keeps the coordinates and connection in JSON Canvas rather than storing a second endpoint representation in the extension. The marker identifies editor-owned point nodes for selection filtering and removal when no edge refers to them. They count towards file limits and take part in geometric group movement. Copying a node includes its attached free points and those connectors. Removing the marker leaves an ordinary empty text node at the same coordinate. No assumption is made about another application's treatment of zero-sized nodes; interoperability remains a C4 check.

20. **Canvas selection follows the source in both directions** (2026-11-04, Paul). Selecting a node or connector selects its complete JSON object and scrolls the source to it without moving keyboard focus. Moving the source caret within that object selects the corresponding drawing item and reveals it when it is outside the camera. The JSON syntax tree supplies object ranges, including escaped property names and IDs; node and edge IDs remain separate. Selection does not rewrite the file. Shape tools live in the Shape menu and its ribbon, with no second palette above the drawing.

21. **Text alignment is independent of shape** (2026-11-04, Paul requested control of text placement). Text nodes have optional horizontal and vertical alignment properties in the documented extension. The inspector offers Left, Centre and Right, and Top, Middle and Bottom. Shape Default removes the corresponding property and preserves the existing shape-dependent defaults. The renderer resolves both values once for the live Markdown and exported SVG text, within the same usable text inset. Each change uses the model and undo history and is available through `canvas-edit@1`.

22. **The ribbon offers drawing tools through a menu button** (2026-11-04). Thirteen shapes plus selection are too many positions for one segmented control. Drawing Tool is a submenu of Shape, which PUDL renders as a menu button in ribbon mode. Paul preferred individual toggles to a radio group, so each shape command carries checked state without choice metadata. Choosing the active shape again clears it; Select and Escape also return to selection mode. The rows retain command glyphs. This uses the existing documented submenu contract and leaves PUDL's general radio-to-segment conversion unchanged.

23. **A selection is a list of node or edge identities** (2026-11-04, Paul requested multiple selection and common properties). Shift-click and Ctrl/Command-click toggle membership, a marquee selects fully enclosed nodes, and Ctrl/Command+A selects all visible items. Edit offers Select All Items and Select Items, whose checkbox dialog permits arbitrary subsets from the keyboard. A normal click on an already selected node preserves the selection for dragging. The source follows the last selected item. The inspector shows only properties every selected item supports; differing values show Mixed until explicitly replaced. One property change, movement or deletion produces one validated source transaction and one undo step. A moved group carries its contained nodes, with the union moved once even when a member is selected separately. Copy, duplicate, ordering, resize dialogs and endpoint gestures retain their single-item requirement and are disabled for multiple selection. Numeric common geometry can still be set through the inspector. The optional `items` array on canvas actions uses `{id, kind}` entries so the two ID namespaces remain distinct.

24. **Inspector resizing uses PUDL's nested splitter** (2026-11-04). The divider is operable by pointer and keyboard and can reset to the default width. Its current proportion is saved through the host configuration service. Split notifications persist the live geometry without writing another size into the layout, so a delayed notification cannot restore an earlier width during a gesture. Short fixed choices use segmented buttons, while long shape and arrowhead lists stay menus. Multiple selection with differing values has no pressed segment until the user chooses a value. Color supplies a native custom-color picker, the six format presets and a default reset.

25. **Frequent tools lead the menu and visual choices carry glyphs** (2026-11-05, Paul). Drawing Tool is the first item under Shape in both Canvas and D2. Canvas Route keeps three segments with route glyphs. Start Head and End Head use PUDL menu pickers so every option can show its endpoint symbol alongside its label and checked state, without depending on native select rendering. Mixed selections have no checked option until a value is chosen. Save As uses a project glyph in Diagrams because the pinned PUDL release has no standard glyph for that command. This changes no file format or drawing behavior.

26. **Inspector segments keep labels beside visual symbols** (2026-11-05, Paul). Horizontal and vertical alignment, including Shape Default, and Line Style gain project glyphs alongside the existing Route glyphs. D2 Line Style uses the same previews. Every segment keeps its words and gains equal extra padding on both sides. In a narrow inspector the glyph sits above the label so four alignment choices fit without cutting off their names; a wider inspector shows them side by side.

27. **Shape text is edited directly with live source updates** (2026-11-05, Paul). Double-click or Enter on one text node opens a plain Markdown text field over that node. Accepted input immediately updates the canonical source through the canvas model and CodeMirror history, so saves, snapshots and close prompts include it. Enter inserts a newline; Escape finishes editing while keeping the accepted changes, and Undo uses the source history. Editing ends on a tab switch or an unrelated source change. The field never renders supplied HTML. Unsupported nodes and multiple selections do not offer Edit Text.

28. **Fill and outline override the coordinated color independently** (2026-11-05, Paul). Optional node properties `yavc.fillColor` and `yavc.strokeColor` accept the format's hex colors and six presets. Removing either restores that channel's coordinated default without changing the other channel or the standard `color` property. The same resolution applies to live drawings and exports. Text ink adjusts for an explicit fill so it remains readable. This is an additive version 1 extension.

29. **Clearing selection exposes diagram settings** (2026-11-05, Paul). The Inspector then edits `yavc.background`, `yavc.grid` and `yavc.snap`. Background defaults to the theme and appears in exports. Grid defaults off, snapping defaults on, and both are editing preferences carried with the document. Grid points follow file coordinates and are omitted from exports. The current snap spacing remains eight file pixels, with Alt temporarily bypassing both grid and shape snapping. Every setting is one validated source edit with Undo.

30. **Canvas templates are editable starting arrangements** (2026-11-05, Paul). New Canvas offers Blank, Basic, Flowchart and Sequence. Templates contain ordinary nodes and edges, including free connector points where needed, and impose no layout rules after creation. They do not claim conversion from D2/Mermaid or a guided layout engine. `new@1` accepts the same template names through its existing style argument.

31. **Inspector width is independent of the visual/text split** (2026-11-05, Paul). The default Inspector width grows to 22rem. Resizing the outer visual/text divider retains the Inspector's chosen pixel width against that divider; the drawing absorbs the change. Explicit Inspector resizing sets a new width. Small hosts temporarily clamp the displayed width without overwriting the preference. Segments keep labels intact, reflow into fewer columns as needed, then show glyphs alone at the narrowest widths with tooltips and accessible names.

32. **Saves acknowledge their submitted document and resource** (2026-11-05). Live inline editing exposed existing delayed-save races in Diagrams. Normal Save, Save As and `save@1` now share a queue per document, capture text before queuing and acknowledge only an open originating tab with the submitted resource and save generation. Same-document writes run in order. An inactive tab can update its own saved path and snapshot without reconfiguring the active editor. Newer text stays modified, and failures retain it. This does not resolve the separate Editor save findings or promise conflict detection against writes made by another application.

33. **Inspector actions keep their natural width** (2026-11-05, Paul). Segments and menu buttons size to their contents instead of growing to fill the Inspector. Whole options wrap when needed; at the smallest pane widths segments retain glyphs, tooltips and accessible names. Text and numeric fields retain the width needed for entry. Theme Default removes the diagram background override, and the renderer reads the host background rather than the previously painted canvas when resolving the theme.

34. **The Canvas Outline shares the current selection** (2026-11-05). View, Show the Outline opens a list of ordinary nodes followed by connectors in file order; private endpoint nodes are omitted. Each row is a PUDL toggle button. A click selects one item, Ctrl or Command toggles it, and Shift extends from the last clicked row. Arrow keys, Home and End move focus; Enter or Space activates the row. The drawing and source select the same item, and an Outline selection reveals it on the drawing. F6 and Shift+F6 cycle the drawing, visible Outline, Inspector and source panes. The drawing receives focus on its stage so its editing shortcuts continue to work. The Outline preference is host configuration. A D2 Outline remains separate work.

35. **Alignment and distribution arrange selected units** (2026-11-05). Shape, Align and Distribute aligns two or more nodes to the selected bounds' edges or centers, or spaces three or more nodes with equal horizontal or vertical gaps. Negative gaps are permitted for overlapping arrangements. The first and last positions remain fixed for distribution, and intermediate coordinates round to whole file pixels. A selected group carries its contained nodes as one unit, including selected descendants. Overlapping groups that demand incompatible movement are refused atomically. Mixed node/connector selections are refused. Each operation is one source transaction with one undo step; `canvas-edit@1` exposes the same operations through `items`, `op` and `direction`.

### Progress

C1 was built on 2026-11-04. `docs/canvas-extension.md` states the extension, version 1. `apps/diagram-kit/jcanvas.js` reads a canvas against the specification and the extension, writes it in the stable form, routes its connectors and draws it as SVG; it needs no DOM, and `apps/diagram-kit/test/jcanvas.test.mjs` tests it under Node from `scripts/check.sh`. Diagrams opens `.canvas` files as a third kind, with JSON colouring and the reader's problems marked in the text, File, New Canvas, Tidy the Text in the stable form, export to SVG and PNG, and the agent actions. On the screen each text node's Markdown is drawn by the Markdown engine and the cleaner in a `foreignObject`, with any applet in it left unstarted; the export keeps the SVG text. The six presets are a fixed set for a light background and another for a dark one, since PUDL's category colours are not the red to purple the specification gives them. Files opens a `.canvas` in Diagrams. The view is read-only, and the drawing is fitted to its contents with a margin; pan and zoom (open question 3) come with C2.

C2 now implements selection, movement, eight resize handles, proportional resizing, grid and shape snapping, pan and zoom, the thirteen-shape palette, side-to-side connectors, the inspector, deletion, duplication, clipboard operations, drawing order and groups. The drawing stays editable through menus and keys; the inspector also exposes geometry numerically. `canvas-edit@1` offers the same model operations to agents without changing D2's existing action. `canvas-view@1` provides selection and camera operations. The DOM-free model tests run in the regular checks. `scripts/test-canvas.cjs` checks the real editor against a disposable server, including the picture/hit alignment, gestures, undo boundaries, source-change cancellation and delayed clipboard completion. C2 remains subject to review and merge.

The remaining work of the D2 editor (the Outline pane, arrow keys along connections, a new shape's place among its siblings) follows the canvas work. The current productivity candidate implements C3's Canvas Outline, pane keyboard access and multiple-selection alignment/distribution. C4's conversion, embedding and Obsidian checks remain to be built.

## Open questions

1. **The extension and other applications.** The specification does not say whether an application must keep properties it does not define. If Obsidian drops `"yavc"` when it saves a canvas, a file edited there keeps its layout, text and connectors but loses its shapes and line styles. The recommendation is to accept that, since decision 2 makes the loss graceful, to check Obsidian's actual behaviour in C4 without building on it, and to ask the format's maintainers to state a rule for extension properties, so the answer becomes a documented one. A draft of that request can be written for Paul to file, as the D2 one was.
2. **Text in exports.** Decision 6 draws Markdown as HTML on the canvas and as SVG text in exports, so an export can differ slightly from the canvas, for example in a code block or a table inside a node. The alternative is SVG text everywhere, which loses most Markdown on the canvas too. The recommendation is the split, with the difference stated in the help page.
3. **An infinite canvas or a page.** The format's coordinates are unbounded, as an infinite whiteboard's are. Diagrams can show the canvas as an infinite surface with pan and zoom, or fit it to its contents like a D2 drawing. The recommendation is pan and zoom while editing, and the contents' bounds, with a margin, for an export or an embed.
