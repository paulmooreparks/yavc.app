# Footnotes

Markdown footnotes use `[^label]` references and indented `[^label]:` definitions. Goldmark's public parsers provide the grammar. A project transformer retains definitions in their original source positions, including unused definitions, and numbers references in reading order. The standard transformer would relocate definitions and remove unused material, so it is not installed.

The rich document keeps references as inline atoms and definitions as editable block content. Insertion creates both in one Undo transaction. Number updates are view maintenance and do not add an Undo entry. Untouched source retains its original spelling, order and indentation. Labels are bounded and validated before serialization. The interface permits at most 256 notes, and the insertion dialog checks the captured document and selection before applying its result.

Every rendered surface assigns its own note IDs. Reference navigation stays within the corresponding document window. The engine emits semantic label and number metadata, without assigning globally shared DOM IDs. Export trusts the parser's definition map rather than authored HTML attributes.

The measured page planner reserves space at the bottom of the first reference's page. Repeated references point to that note. Page notes remain source nodes, with source-free position decorations. Print clones each placed definition once. Definitions nested inside quotations or lists currently produce explicit page-layout guidance; oversized page notes also remain a visible limitation while continuation in the interactive page planner is completed. Visual and Text views retain those sources.

Word export uses native editable footnotes. Repeated references use a NOTEREF field whose bookmark and cached value are generated from validated numeric IDs. Exclusion pruning happens before export numbering, so hidden references and unused definitions do not create notes or expose their assets.

PDF export with notes uses a separate measured writer because the existing pdfmake public interface has no native page-footnote layout. PDF-lib 1.17.1 supplies documented font measurement and drawing APIs. The writer embeds the same four Roboto variants already bundled for PDF, wraps styled runs into bounded lines and reserves page-bottom note space. Long notes continue on subsequent pages. Text stays selectable, references become local PDF links, and source content remains unchanged. Body paragraphs, lists, quotations, images, rules and rectangular tables retain the structured export model. Table headers repeat across pages. Footnote bodies support paragraphs, lists, quotations and pictures; nested references, note tables and explicit note page breaks are refused with guidance. PDF font substitution can change line and page breaks relative to the editing surface, as it already does for ordinary PDF exports.

The writer limits documents to 1,000 pages and 200,000 measured lines. Export still applies the existing Markdown, image, decoded-pixel, aggregate-image and unsafe-layout limits. Unsupported glyphs fail visibly rather than being silently dropped. The public API basis is the [Goldmark parser API](https://pkg.go.dev/github.com/yuin/goldmark/parser), [docx footnote API](https://docx.js.org/api/classes/index.FootnoteReferenceRun.html), [docx field API](https://docx.js.org/api/classes/index.SimpleField.html) and [PDF-lib API](https://pdf-lib.js.org/docs/api/).
