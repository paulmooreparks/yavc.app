# Persisted document review

Docs uses the five CriticMarkup forms selected in decision 11 of `docs-design.md`. Additions use `{++new++}`, deletions use `{--old--}`, replacements use `{~~old~>new~~}`, comments use `{>>comment<<}` and highlights use `{==text==}`. This follows the [CriticMarkup toolkit's syntax](https://github.com/CriticMarkup/CriticMarkup-toolkit/blob/master/README.md). Existing transient agent suggestions remain independent.

The Markdown engine discovers marks only where Markdown permits ordinary text. Code fences, inline code, escaped openers, HTML tags, metadata and link destinations cannot supply review commands. Once a valid opener establishes a mark, its closing delimiter bounds its raw source body, including paragraph breaks. Nested or incomplete forms are reported and retained literally. Limits bound the source, number of marks and individual bodies. Closing delimiters within a proposed body must be escaped or the proposal must be refused before insertion.

The catalog returns the original raw form, kind, body ranges and UTF-16 source offsets. The frontend captures the complete source used to produce it. Accept, Reject, editing a proposal and whole-document resolution all require that captured source to remain current. A rendered identifier is only a navigation hint. Every mutation is one normal source edit covered by Undo, raw line-ending provenance, dirty-state tracking and recovery.

A rich selection is mapped with a temporary public ProseMirror transaction containing unique plain-text sentinels. The engine serializes that temporary document without dispatching an edit. Removing the sentinels must reproduce the complete current source exactly before the resulting offsets can be used. A selection whose Markdown boundaries cannot be mapped safely is refused with guidance to use Text. This avoids a second approximate Markdown position mapper and leaves source, history and selection unchanged during the probe.

Accept keeps an addition or the new side of a replacement and removes a deletion. Reject removes an addition, restores a deletion or keeps the old side of a replacement. Resolving a comment removes its annotation; resolving a highlight keeps its text. Accept All and Reject All resolve the nonoverlapping catalog in one pass. Malformed or nested markup remains untouched and is reported.

The Review menu proposes changes and comments, navigates existing marks, and resolves individual or all marks. A searchable review list shows kind, text and source location. Comments use the front matter author when available and remain plain source text. Dialogs show ordinary labelled controls and cancel on disposal or an obsolete document. Comments and suggestions are persisted annotations; this effort does not silently enable automatic tracking of ordinary keystrokes.

The rendered document distinguishes inserted and removed content with semantic ins/del markup and glyph/status cues. Comments remain navigable in both rich and read-only views. A rich representation must retain the complete original source until edited. A form that cannot round-trip safely stays source-editable and remains fully available through the review list.

Exports must not silently choose a side. Documents containing unresolved changes require an explicit reviewed output policy, with the source left unchanged. Comments are omitted from clean output. The chosen accepted/original projection runs before export exclusions and footnote numbering so rejected references, headings or notes cannot leak into the destination. Existing code examples containing literal CriticMarkup remain ordinary content.
