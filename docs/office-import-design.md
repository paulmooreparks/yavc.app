# Office import

Office import creates a new native document and leaves the source package unchanged. Docs exposes Import Word and Slides exposes Import PowerPoint. Both use the host file picker with computer upload where available. A receiving host may provide bounded bytes through its documented contentBytes extension; an applet cannot bypass that authority with a URL read.

DOCX conversion runs in a disposable worker using Mammoth 1.13.0's documented browser API. The worker has a 30-second deadline. Compressed input is limited to 8 MiB, each expanded part to 8 MiB, all expanded parts to 32 MiB and the archive to 1,024 entries. Every entry is counted through JSZip's documented stream before a new bounded archive reaches Mammoth. Invalid paths, DTDs, malformed XML and unsupported package types fail before conversion. Embedded style maps and external file access are disabled.

The generated HTML is untrusted. It remains inert until the shared HTML cleaner and page schema read it. Headings, paragraphs, lists, ordinary tables, links and supported character formatting become native Markdown. Footnote and endnote definitions become Markdown footnotes. Embedded PNG, JPEG and GIF images become data URLs within a combined 128 KiB budget. Header dimensions cannot exceed 16,384 pixels on either side or 16 megapixels in area. Unsupported or excessive images are omitted with a report. Native source is limited to 256 KiB so that it can be saved by the guest resource authority. The importer refuses a larger result without changing an open document. Converted HTML is limited to 20,000 nodes and 64 levels of nesting; Office XML is limited to 100,000 element nodes and 64 levels across the package.

The report describes semantic conversion, retained notes and images, and detected losses. Page positioning, floating objects, section geometry, headers/footers, comments and tracked-change metadata require explicit reporting. The original package remains available for features the native format cannot represent. The interactive report must be accepted before the new copy opens, and Cancel leaves the current document unchanged. The existing PowerPoint import action retains its noninteractive contract and returns the report with its authorized new copy. This conversion does not claim round-trip fidelity to Office layout.

PPTX conversion retains text, supported lists/tables, speaker notes and bounded embedded raster pictures. It reports charts, diagrams, unsupported images and presentation layout or animation losses. Titles are serialized as quoted YAML scalars. Hyperlinks and imported content use the same sanitation rules as native source.

Literal Office text receives a complete Markdown punctuation escape pass, including HTML/entity openers and deck separators. Inferred titles use the original plain text rather than reverse-parsing generated Markdown. Tables escape pipes once. Imports retain the initiating document identity across file reads, worker conversion, report dialogs, rich synchronization and native-copy creation. A delayed completion cannot adopt another active document as its owner.

The raster header guards follow the [PNG IHDR specification](https://www.w3.org/TR/png/#11IHDR), [GIF89a logical screen descriptor](https://www.w3.org/Graphics/GIF/spec-gif89a.txt), and [JPEG T.81 frame header](https://www.w3.org/Graphics/JPEG/itu-t81.pdf). They impose admission limits before browser decoding; they do not replace the browser's format validation.
