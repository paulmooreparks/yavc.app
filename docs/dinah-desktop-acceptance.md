# Dinah desktop acceptance proof

The receiving-host proof uses a clean detached Dinah checkout at `ba2b8b72008e53fc1b8601f5d903ce95fa53558d` and the exact extracted content artifact under test. It runs Dinah's actual Wails 2.11.0/WebView2 window in its existing hidden test mode, with a new `DINAH_HOME`, temporary synthetic workspace and separate browser profile. It neither replaces the installed executable nor loads the person's settings, documents or credentials.

The proof changes the test build through Go's documented build overlay. The overlay selects a composite read-only asset filesystem only when both the hidden-test entry file and proof directories are supplied. Its one worker-policy adjustment applies to the exact packaged D2 worker route. The page retains Dinah's normal authenticated loopback bridge and its normal restrictive page policy. The producer artifact remains unchanged, with its full file manifest checked before use.

The host fixture uses `SetWorkspace`, `ReadWorkspaceResource`, `OpenDraft`, `GetDraft`, `UpdateDraft` and `SaveDraft` against copied synthetic files. Both the draft revision and persisted resource baseline remain checked by Dinah's own services. The fixture must reject unpresented native draft changes, retain a failed save's draft and keep competing resource writes conditional. It does not become a production document authority or install yavc.app's guest filesystem.

The proof's preference and snapshot fixture is scoped to the isolated profile. Any durable acknowledgement must follow the native host's acknowledgement. An asynchronous write cannot make the synchronous snapshot flush report success before it completes. A single serialized owner may use Dinah's complete UI-state store in this isolated proof; a production adapter must reconcile that store with the real shell's existing writer.

The acceptance run checks real source and rich edits, independent applet ownership, conditional saves and conflicts, Markdown and Canvas preservation, document pagination, browser-local language workers, offline dependency loading and disposal. The actual WebView2 runtime and the producer/receiver revisions belong in its receipt. Linux and macOS webviews require their own receiving-host runs.

Microsoft documents the [WebView2 debugging environment variable](https://learn.microsoft.com/en-us/microsoft-edge/webview2/how-to/debug-visual-studio-code), and Playwright documents [connecting to WebView2 through CDP](https://playwright.dev/docs/webview2). The first attempt found that Dinah's pinned Go WebView loader clears environment and registry browser-argument overrides. That failed attempt remains in its log. The proof retains the receiving loader and instead executes page-owned checks in the real WebView, reporting through the existing authenticated native bridge and native UI-state acknowledgement. It does not automate the shared desktop or take foreground focus.

The first native run verified all 483 artifact hashes and completed a source save through the real native draft/resource services. It then exposed missing host registrations for the project-defined `files.read` and `files.write` action capabilities. Their absence caused PUDL to refuse the complete action manifests. The fixture now declares those bounded capabilities while exposing only native reads and conditional resource writes. It does not add an unconditional filename writer. Independent browser fixtures now check those action manifests and invoke their public read actions as well.

Prepared proof reuse verifies the receiver paths, complete artifact hashes, original receiver source hashes and generated overlay hashes. The build pins the clean extension checkout too. The runner records hashes for its exact fixture scripts separately from the immutable producer artifact. A preparation regression rejects altered overlays, receiver source, artifacts, duplicate manifest entries and escaping paths.

The initial rerun was blocked when automatic approval review could not authenticate because its refresh token was revoked. The independent review agent failed with the same error. No alternate launch route was used. The ordinary-permission full gate also stopped at its network-restricted vulnerability check. Approval service access subsequently resumed, the full repository gate passed, and the native test ran through the normal approval path.

The successful run against artifact `f9ebf476171fbb0a90ef5db1068de8c0ea2e390933dbf6fadad64db208c55ec1` verified all 483 assets in Edge WebView2 157.0.0.0. It passed native source and rich saves, review resolution and Undo, Canvas extension retention and saves, D2 WebAssembly, CSS/HTML worker completions, measured page footnotes, competing-native-draft refusal, subscription disposal and acknowledged recovery persistence. The isolated receiver was `ba2b8b72008e53fc1b8601f5d903ce95fa53558d` with extension `444129580fb6f8f8d3ce3248a09f8df97c6699ac`. The runner retains hashes of the exact host/check scripts and native executable with each result. Intermediate runs exposed two test-harness mistakes, a Close-button selector and an unexported completion helper, whose failed receipts remain separate from the successful run.

Independent source review found the read capability provider also exposed the conditional resource writer. The fixture now omits that service from capability contexts entirely. Live save actions continue to use their own conditional host boundary after PUDL checks the declared write grant.

The production replacement remains a separate adoption decision. The cousin agent can use this proof, adapter mapping and exact artifact receipt when integrating with Dinah's main shell and recovery owner. This document records the acceptance method; it does not claim a completed native run before the receipt exists.
