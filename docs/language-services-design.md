# Shared language services and LSP

Paul chose a shared integration for Editor and Diagrams on 4 November 2026, and confirmed that JSON Canvas remains the freeform diagram format. The first implementation supplies a browser-local JSON language server to both applications. D2 keeps its existing worker completion provider. Mermaid and other languages do not gain an LSP server in this round.

## Decisions

1. **Both editors use one integration.** `apps/md-editor/language-service/bridge.js` owns the CodeMirror LSP client, worker transport, document identities, diagnostics and formatting safeguards. Each application instance creates and disposes its own session. The hosts supply the language kind, read-only policy and PUDL notice callback; storage and save authority remain with the host.
2. **The first server runs entirely in the browser.** The official `@codemirror/lsp-client` 6.3.0 talks JSON-RPC to a classic browser worker. The worker wraps Microsoft's `vscode-json-languageservice` 5.6.4 and `vscode-languageserver-textdocument` 1.0.12. It implements the LSP 3.17 subset it advertises: UTF-16 positions, incremental text synchronization, completion, hover, versioned diagnostics, document formatting, cancellation and shutdown. No server process, socket or source upload is involved.
3. **Schemas are bundled.** Ordinary JSON receives syntax assistance. Files ending in `.canvas` also receive a schema for JSON Canvas 1.0 and the documented yavc extension, including shape, alignment, route and arrowhead values. Document-supplied `$schema` addresses cannot cause network requests. Unknown properties remain allowed. The existing canvas reader retains semantic checks such as references, editor-owned point anchors and supported resource handling.
4. **Every active open instance has a fresh virtual URI.** A random application-session prefix and increasing document generation distinguish tabs, reopened paths and independent windows. Physical file paths never reach the worker. The CodeMirror workspace maintains increasing revisions within an open instance. A tab activation closes the prior active instance and opens a new generation; each host retains its tab's editor state and undo history.
5. **Late results cannot change another document.** The server snapshots each document revision and rejects requests whose document record changed or closed before completion. The client validates diagnostic URI and version. Formatting additionally checks client, plugin instance, document identity and read-only state before applying validated edits through one CodeMirror transaction. Completion uses CodeMirror's request lifecycle and retains the language server's complete JSON-token edit range while filtering on the prefix before the cursor.
6. **Assistance can stop without losing the buffer.** A failed worker is terminated, pending requests are settled and the mounted language plugins are replaced with native JSON syntax diagnostics. Restart Language Assistance creates a new session connection. Documents above 2,097,152 UTF-16 code units suspend assistance with a PUDL notice and reopen under a fresh URI when they shrink. The protocol also bounds open documents and outstanding requests. Closing an application disposes its client and worker.

## Commands and diagnostics

Ctrl+Space requests completion. Hover displays schema documentation after cleaning the generated HTML with the existing shared sanitizer. Shift+Alt+F formats JSON in either editor; Editor also offers Format JSON in Edit. Read-only documents retain hover and diagnostics but have no language completion provider or formatting edits. Both applications offer Restart Language Assistance in Edit for eligible documents.

Diagrams keeps Tidy the Text as its existing canonical canvas writer. LSP formatting changes whitespace while preserving property order; it does not replace that command. Canvas renderer diagnostics and schema diagnostics share CodeMirror's lint infrastructure. A refresh effect schedules linting when a diagnostic response arrives after the ordinary idle check has already run.

Editor and Docs retain their Markdown extensions. The November 9 catalog batch removes the inherited Parks admin request. Built-in completion and hover use the bundled engine's names, parameter descriptions and argument requirements, with optional bounded host additions. Named parameters, required colons, optional-only arguments and container/span closers work without network access once the local engine is loaded. Plain source editing does not load Markdown merely for the catalog or an empty Outline. D2 completions continue through the pinned D2 worker's `d2lsp.GetCompletionItems` API.

## Build and verification

The [build instructions](../apps/md-editor/language-service/README.md) describe the pinned dependencies, artifact hashes and license provenance. npm dependencies are installed in a temporary build directory outside the served applet tree. Both CodeMirror and the worker are vendored as self-contained bundles, so starting language assistance requires only assets from this host. The maintained upstream client source is [CodeMirror's forge](https://code.haverbeke.berlin/codemirror/lsp-client); Microsoft's [JSON language service](https://github.com/microsoft/vscode-json-languageservice) supplies the language implementation behind our protocol adapter.

The module tests exercise the built worker, artifact hashes, schema shape parity, completion, hover, formatting, versioned diagnostics, cancellation, close/reopen and refusal of external schemas and oversized opens. `scripts/test-language-services.cjs` exercises both consumers in Chromium, Firefox and WebKit, including completion acceptance, hover, diagnostics, formatting/undo, stale formatting responses, independent document identities, worker failure/restart and size suspension/recovery. Its shared-boundary fixture also checks initial oversized mounting and read-only formatting. Tests intercept analytics; the obsolete empty-catalog stub is removed. `test-shortcode-catalog.cjs` separately verifies Editor and Docs completion/hover offline after initialization, cold plain-source startup and held-engine disposal in all three engines. These checks do not claim that a cached web application can launch offline.

Workspace edits, rename, definition navigation, semantic tokens and server-process transports remain outside this slice. A desktop adapter can reuse the shared integration, but replacing the desktop editor still requires the save/recovery and host-contract gates in the [Dinah integration brief](dinah-editing-integration-brief.md). No Dinah integration is claimed by these browser tests.
